| S17 | `dispatch.Tools` — the declared operations become MCP tools, with no MCP dependency | 2026-09-23 | Built for DSN-1724: the `mine-agencies` routine is to file what it mines through `mwanachama-wakala-api`'s MCP, and the module it would write to (`mwanachama-backend-catalog`) has no hand-written handler left to hang a tool on and may not carry a domain's words anyway. So the tools come from the same `*.operations.json` the routes do. **No SDK dependency here:** a `Tool` carries `InputSchema` as `json.RawMessage` and `Invoke` as `func(ctx, json.RawMessage) (any, error)`, so `go.mod` is untouched and the ~20-line adapter onto `modelcontextprotocol/go-sdk` lives in the process that already imports it. **One flat object of arguments:** a named argument is its own property; a `whole` body or query is spread one property per field (by `json` tag, or by `query` key for a query struct) and reassembled before the call; an `into` argument replaces the field it overwrites, so `slug` appears exactly once and the address-outranks-the-body rule holds by construction rather than by ordering. `mwanachama-backend-shared` — Go library, module `github.com/aosanya/mwanachama-backend-shared`.
No audience of its own; a dependency of [mwanachama-backend-git](../../../mwanachama-backend-git)

wired into [mwanachama-backend-api-gateway](../../../mwanachama-backend-api-gateway) for
[mwanachama-frontend-kazi](../../../mwanachama-frontend-kazi).

### Why this repo exists

`CodeValdGit` and `CodeValdWork` are ArangoDB-backed Go libraries built for
CodeValdCortex agencies. `mwanachama-frontend-kazi` needs the same git-like versioned
content and task/workflow management, but `mwanachama-backend-api-gateway` standardizes
on Postgres and runs as a single service (no sub-services). Both source
libraries lean on a shared package, `CodeValdSharedLib/entitygraph` — a
generic entity/relationship graph store — for almost everything that touches
storage; their own business logic (`git_impl_*.go`, `task*.go`) is already
storage-agnostic Go that only calls the `entitygraph.DataManager` interface.

Porting that one shared engine to Postgres once, here, means
`mwanachama-backend-git` and `mwanachama-backend-taskmanager` can port their respective
business logic with minimal churn instead of each reinventing entity/edge
storage and graph traversal.
