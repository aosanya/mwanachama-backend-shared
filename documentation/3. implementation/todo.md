| S26 | ⚠️ **A physical name has no room for a second mount of the same module, so two Catalogs in one tenant silently share tables.** `Spec.TableFor` (`spec/spec.go:238`) emits `<instance>_<module>_<object>` — three segments — and `SegmentPattern` (`spec.go:40`) refuses an underscore inside the first two, held by `TestValidate_RefusesAnUnderscoreInASegment`, so a second name cannot be smuggled into the instance segment either. A tenant that mounts the same module twice therefore gets one table set, and per `mwanachama-backend-taskmanager`'s own CLAUDE.md the failure is silent: GORM's `AutoMigrate` adopts an existing table and `spec.Migrate`'s create-if-not-exists is a no-op against one. **Decision (owner, 2026-09-29): add a fourth segment** — `<instance>_<module>_<mount>_<object>`. Segment 1 keeps its current meaning (the agency's `tableSlug()` for per-agency modules, the configured spec instance for a global one) and its current value, so the data migration is a pure segment *insert* rather than a rewrite, and the existing `instance` key in all 19 shipped domain specs is untouched. **Naming**: the new field is `Spec.Mount`, not `Instance` — `Instance` already firmly means "a registered agency" next door in `mwanachama-wakala-api` (`agencies.Instance`, `/instances/{instanceID}`, `agency_instance_members`), and `Mount` matches the vocabulary already there (`catalogroutes.Mount`, `mountedModule`, `mountedOperations`). ⚠️ *Confirm the word with the owner before the sweep lands — it reaches every spec file and every table name.* **Budget checked and it fits**: worst identifier shipped today is 48 bytes (`<inst11>_taskmanager_work_items_objective_idx` and `<inst11>_taskmanager_task_project_memberships`), so a 4-char mount lands at 53 against `MaxIdentifier` 63, leaving ~14 chars for a mount name on the worst case. `validate.go`'s `claim` already measures every emitted name and refuses an over-long one at load, so a too-long mount is a startup refusal, not a silent truncation — no new guard needed, but the mount segment wants its own length cap so the refusal names the right thing. Scope here: `Mount` on `Spec`, threaded through `TableFor`/`IndexFor`, validated as a segment, plus the default when a spec declares none. | 🚀 | — |
