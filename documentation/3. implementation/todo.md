| S43 | 📋 **A spec cannot declare an expression or GIN index, so a full-text index has to be applied beside `spec.Migrate` rather than by it.** `spec.Index` is over columns (`fields`) or over a document path (`path`), and `migrate.go` emits a btree either way — there is no `method` and no way to name an expression. `mwanachama-backend-git`'s blob search is a Postgres `to_tsvector('english', coalesce(name,'') || ' ' || coalesce(content,''))` GIN index, so its `Provision` runs `spec.Migrate` and then applies that index itself, and `cmd/ddl` prints it as a trailing statement outside the generated block. That works, but it means the spec is no longer the whole storage story for that module, and a second module wanting full-text search will write the same thing again. **The hard part is not the index, it is the expression**: `Index.Where` is named conditions rather than free SQL precisely because free SQL is an injection surface, and an expression index needs the same discipline — a small closed vocabulary (`to_tsvector` over named columns, with a language) rather than a string the domain supplies. Worth doing only when a second module needs it; one consumer is not yet a pattern. | 📋 | — |

| S39 | 🐞 **BUG — an adopted legacy table keeps its old column *types*, and a declared `timestamp` is `text`, so `AdoptLegacy` leaves a Postgres schema the codec cannot read.** `Field.columnType` (`spec/migrate.go`) emits `text` for `string`, `text`, `timestamp` and `enum`. | S38 | 📋 **`specstore` carries `time.Time`, and a carrier the codec cannot read is now refused instead of stored as reflect's placeholder.** Two changes, one cause. (1) A declared `timestamp` may now be carried as a `time.Time` or `*time.Time`, not only as a `string` holding RFC 3339 — `specstore.TimeLayout` is the stored form, fixed-width with nine fractional digits and always UTC, because a timestamp is a `text` column and `ORDER BY` over it is a string comparison: `RFC3339Nano` trims trailing zeros and would sort `.5Z` before `.05Z`, and a preserved zone offset would sort two identical instants apart. Reading accepts that layout, `RFC3339Nano`, a Postgres `timestamptz` rendering, a bare `2006-01-02 15:04:05`, and a driver-returned `time.Time`. (2) **`cell` used to end in `return fv.String(), nil`, and `reflect.Value.String()` does not panic on a non-string kind — it answers `"<time.Time Value>"`.** So a `time.Time` or a `[]byte` on a declared `string` or `timestamp` column was silently written as that placeholder text, with nothing failing until the row was read back; demonstrated before the fix by encoding a probe object and reading `"<time.Time Value>"` and `"<[]uint8 Value>"` straight out of the row map. `cell` now refuses any kind it has no arm for, and `int`/`float`/`bool` are guarded the same way rather than relying on `reflect`'s own panic. Guards in `specstore/time_test.go`, three of them mutation-checked (trimming the layout, dropping the UTC normalisation, and removing the kind guard each turn one red). **Found converting `mwanachama-backend-comm`**, which has ~23 `time.Time` fields and is the first module not already carrying its timestamps as text. ⚠️ **Note this makes two conventions available where there was one**: catalog, agency, accounting, forms, taskmanager, permissions and digitaltwin all carry timestamps as `string` and are untouched. Whether they should move onto `time.Time` is the owner's call and is deliberately not assumed here. | 📋 | — |

| S36 | 📋 **`spec:"-"` lands; check whether any converted repo dropped a derived field to get past the cross-check.** `specstore.New`'s `disagreements` refuses a carrier field the object does not declare, which is right for a typo and wrong for a field that is genuinely read from somewhere else — a join table, an inverse FK, an in-process map.
