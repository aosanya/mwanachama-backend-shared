| S32 | ⏸️ **PARKED (owner 2026-09-30: revisit with a slow interface to illustrate) — "the software is slow because we have no indices" is not what the evidence says.** **142 indexes are declared across the nine blueprints and `spec.Migrate` does create them**, plus every `primary`/`unique` field emits a constraint Postgres backs with an index (`migrate.go`'s `column()`), so a first audit that counted only `indexes[]` over-reports badly — catalog's `slug`, the hottest lookup in that module, is `unique` and therefore indexed. Counting properly (primary, unique, or the **leading** column of a declared index — a composite only serves a lone filter on its first column) leaves 63 uncovered hot columns, and **25 of those are `deleted`, which is never filtered on read anyway**: neither `specstore.Query` nor agency's `q()` adds a soft-delete predicate. So indexing `deleted` would buy nothing. **The three real candidates, in likely order of cost:** (1) **no `LIMIT` anywhere** — S24 here, plus WK36/CAT10/PM8 on sibling boards — so every list reads and serialises the whole table; this is the one to measure first. (2) **`ORDER BY ordinality` with nothing supporting it** — every agency list sorts its whole result (`goal_impl.go`'s `ListGoals` is representative). (3) **`LOWER(col) LIKE '%x%'`** (`draft_impl.go`'s `likeFilter`, used by all 17 `List*` methods since AG18) — a leading-wildcard match on a function of the column, which **no btree index can ever serve**; it needs `pg_trgm`/GIN or a different search design, not another btree. Engine support that already exists and is barely used: `Index.NotDeleted` emits a partial index and only **9 of 142** declared indexes use it. ⚠️ **Incidental, unverified, and worth its own row if confirmed**: nothing filters `deleted` on read, so either agency deletes hard (it does — `DeleteGoal` calls `deleteWhere`, not a flag update) and the `deleted` columns are vestigial, or some path soft-deletes and those rows are being returned. Establish which before touching any of this. | ⏸️ | S24 |

Demonstrated live against the package's own fixture domain (`store_test.go`'s `ticket` role): seeded 150 tickets, called `specstore.List[Ticket](st, st.Query(ctx, roleTicket), roleTicket)` with no `.Limit` on the query — real output: all 150 rows returned in one `[]Ticket`.
