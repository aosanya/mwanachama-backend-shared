| S17 | 🐞 **BUG — `dispatch`'s HTTP route surface silently accepts a request missing a field the very same spec marks `required:true`, while the MCP tool surface built from that identical spec correctly refuses it.** `dispatch/tools.go`'s `Invoke` checks `Arg.Required` before calling the manager (`TestAMissingRequiredArgumentIsRefused` already pins this for the tool surface); `dispatch/dispatch.go`'s `bind`/`bindOne`/`fromText` never reference `Arg.Required` at all — grepped, the only two call sites of `.Required` in the whole package are in `tools.go`. Demonstrated live with the package's own `toolSpec` fixture (`tools_test.go`), which declares the `issue` operation's `label` argument `{"from":"body","as":"label","required":true,...}` and is dispatched as both a tool and an HTTP route from one `*dispatch.Spec`: calling the MCP tool `t_link_issue` with `{"slug":"one"}` (label omitted) correctly returns `t_link_issue needs "label"`; mounting the identical spec's routes on a real `http.ServeMux`/`httptest.NewServer` and posting `POST /notes/one/links` with body `{}` returns `200 OK` — the manager's `Issue(ctx, "one", "")` is called with a silently zero-valued `label`, no 400, no error. The dispatcher's own design doc (`documentation/2. design/dispatcher.md`, "The same spec as MCP tools") states the point of sharing one spec across both surfaces is that "the schema a model reads and the column the write lands in cannot drift apart" — this is exactly that drift, in the opposite direction (the *stricter* surface is MCP, the *looser* one is the HTTP route a browser or curl actually hits). Every future module adopting `dispatch` (the doc names actor/assetmanager/comm/forms/git/catalog as the duplication this package replaces) inherits the gap the moment it marks any HTTP-bound argument `required:true` and relies on that being enforced. Defect location: `dispatch/dispatch.go`'s `bind`/`bindOne` — needs the same `Arg.Required` check `tools.go`'s `Invoke` already has, returning a 400 rather than proceeding with a zero value. | 📋 | — |
