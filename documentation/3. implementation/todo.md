| S36 | 📋 **`spec:"-"` lands; check whether any converted repo dropped a derived field to get past the cross-check.** `specstore.New`'s `disagreements` refuses a carrier field the object does not declare, which is right for a typo and wrong for a field that is genuinely read from somewhere else — a join table, an inverse FK, an in-process map. Before this there was no way to carry one: the options were to delete the field (breaking whatever JSON contract depended on it) or to keep a separate row struct and hand-written converters, which is the `gormstore/` shape the standard exists to delete. `carriedFields` now skips a field tagged `spec:"-"` in all four struct walks — `disagreements`, `ColumnsOf`, `Encode`'s `fieldsByColumn`, and `Decode` — so such a field is never a column, never written and never read, and its owner fills it. An **untagged** extra field is still refused by name, which is the direction that catches the typo. Found converting `mwanachama-backend-git`, which has six: `Commit.ParentIDs`, `Tree.BlobIDs`, `Tree.SubtreeIDs`, `Tree.CommitID`, `Keyword.ChildIDs` (all read from join tables or an inverse) and `Blob.TreeID` (declared for JSON-contract compatibility and never populated at all). **The follow-up is a sweep, not a fix**: catalog, agency, taskmanager, permissions, forms, digitaltwin, assetmanager and actor were all converted while the only way past the cross-check was to delete the field, so any derived value one of them used to expose may have been quietly dropped from its API rather than carried — worth checking each against its pre-conversion type before assuming none was. Guards: `specstore/derived_test.go`, all four mutation-checked (ignoring the tag turns three red). | 📋 | — |
| S35 | ⏸️ **`required` on an operation argument is documentation, not a gate — and two repos already depend on each reading.** `dispatch.Arg.Required` is read only by `tools.go` (the MCP tool schema's `required` list) and by `Validate`'s refusal of a required *caller* argument. The HTTP path never consults it: `bindOne` binds an absent query or body argument to the zero value and the call proceeds. So a spec saying `{"from":"query","as":"location_id","required":true}` is not enforced on any HTTP request. **Found converting `mwanachama-backend-assetmanager`**, whose hand-written `GetAssetBalance` handler refused an absent `location_id` with a 400 precisely so it would not read as "balance nowhere", which is always zero and hides the caller's mistake — declaring it `required` did not reproduce that, and the repo's own test caught the 200. **Enforcing it was tried and reverted**, because `mwanachama-backend-permissions` depends on the opposite reading: `routes/empty_subject_security_test.go` asserts that `GET /permissions/check` with `subject=` *and* with no `subject` at all both answer **200 `false`** — an empty subject must fail the check without the endpoint erroring — while that repo's spec declares `subject` required. | S32 | ⏸️ **PARKED (owner 2026-09-30: revisit with a slow interface to illustrate) — "the software is slow because we have no indices" is not what the evidence says.** **142 indexes are declared across the nine blueprints and `spec.Migrate` does create them**, plus every `primary`/`unique` field emits a constraint Postgres backs with an index (`migrate.go`'s `column()`), so a first audit that counted only `indexes[]` over-reports badly — catalog's `slug`, the hottest lookup in that module, is `unique` and therefore indexed. Counting properly (primary, unique, or the **leading** column of a declared index — a composite only serves a lone filter on its first column) leaves 63 uncovered hot columns, and **25 of those are `deleted`, which is never filtered on read anyway**: neither `specstore.Query` nor agency's `q()` adds a soft-delete predicate. So indexing `deleted` would buy nothing. **The three real candidates, in likely order of cost:** (1) **no `LIMIT` anywhere** — S24 here, plus WK36/CAT10/PM8 on sibling boards — so every list reads and serialises the whole table; this is the one to measure first. (3) **`LOWER(col) LIKE '%x%'`** (`draft_impl.go`'s `likeFilter`, used by all 17 `List*` methods since AG18) — a leading-wildcard match on a function of the column, which **no btree index can ever serve**; it needs `pg_trgm`/GIN or a different search design, not another btree.
